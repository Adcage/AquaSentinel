## 4. ADC 采样偏低问题调试全记录

### 4.1 问题现象

板上实测时电量页显示异常：

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| BAT | 1.71V | 3.84V |
| PCT | 0% | ~70% |
| RAW | ~1000 | ~2386 |

电池实际电压约 3.9V，100k/100k 分压后 PA0 应读约 1.95V，但修复前 ADC 只读到约 0.85V。

### 4.2 根因分析

#### 4.2.1 直接原因：ADC 采样时间不足

Arduino STM32 官方核心对 STM32F1 的 `analogRead()` 默认使用 `ADC_SAMPLETIME_13CYCLES_5`（13.5 个 ADC 时钟周期）。这在源阻抗较高时会导致采样保持电容充电不充分。

具体机制：

```
ADC 采样保持电容 ≈ 8pF（含寄生电容）
源阻抗 = R1 ∥ R2 = 100k ∥ 100k = 50kΩ
RC 时间常数 = 50kΩ × 8pF ≈ 400ns

13.5 cycles @ 12MHz ADC 时钟 ≈ 1.125μs 采样窗口
239.5 cycles @ 12MHz ADC 时钟 ≈ 19.96μs 采样窗口
```

源阻抗 50kΩ 时，1.125μs 不足以让采样电容充到真实电压；改为 239.5 cycles（约 20μs）后电容可以充到 99.99% 以上。

#### 4.2.2 什么是阻抗和源阻抗

**电阻**是材料对电流的阻碍程度，单位是欧姆（Ω）。

**阻抗**是电阻概念的推广——在直流电路中，阻抗等于电阻；在交流电路中，阻抗还包含电容和电感的效应。

**源阻抗**是指一个信号源在提供电压的同时，内部有多大的"内阻"限制它能供出的电流。

直觉类比：

- 水塔直接接水管 = 低源阻抗，水压足，出水快
- 水塔经过一根很细的管子再接水管 = 高源阻抗，水压损失大，出水慢

在电池采样电路中：

```
电池 3.9V ── R1(100kΩ) ──┬── R2(100kΩ) ── GND
                           │
                      BAT_SENSE → PA0 → ADC
```

PA0 往 ADC 内部看，等效源阻抗是 R1 和 R2 的并联值：

```
R1 ∥ R2 = 100k × 100k / (100k + 100k) = 50kΩ
```

50kΩ 对于 STM32F1 的 ADC 来说属于**高源阻抗**。

#### 4.2.3 ADC 采样保持电容的工作原理

STM32 的 ADC 内部有一个小电容（约 4~8pF），采样过程：

1. **采样阶段**：ADC 内部开关打开，外部信号通过 PA0 给这个小电容充电
2. **开关关闭**：ADC 断开外部，锁定电容上的电压
3. **转换阶段**：把电容上的电压转换成数字值

电容充电遵循指数曲线：

```
V_capacitor(t) = V_target × (1 - e^(-t / RC))
```

- 充到 63% 需要 1 个 RC（约 400ns）
- 充到 99% 需要 5 个 RC（约 2μs）
- 充到 99.9% 需要 7 个 RC（约 2.8μs）

实际还要考虑开关电阻和寄生电容，需要的时间更长。

#### 4.2.4 采样时间对比

| 配置 | 采样时间 | 对 50kΩ 源阻抗 | 效果 |
|------|----------|----------------|------|
| 13.5 cycles (原默认) | ~1.1μs | 电容充不到真实电压 | 读低 |
| 239.5 cycles (修改后) | ~20μs | 电容充到 99.99% | 准确 |

### 4.3 修复内容

**文件**：`firmware/stm32-ptz/lib/battery_monitor/BatteryMonitor.cpp`

#### 4.3.1 STM32F1 专用 ADC 直接控制

不再依赖 Arduino 核心的 `analogRead()`（它每次调用都重新初始化 ADC、使用默认短采样时间），改为直接使用 HAL API：

- 手动配置 `ADC_SAMPLETIME_239CYCLES_5`（F1 最长采样时间）
- 每次采样前执行 `HAL_ADC_Init` + `HAL_ADCEx_Calibration_Start`
- 先丢弃 1 次预读 + `500μs` 稳定期
- 连续采样 16 次取均值，每次间隔 `200μs`
- 非F1平台保留 `analogRead()` 降级实现

#### 4.3.2 采样参数对比

| 参数 | 修复前 | 修复后 |
|------|--------|--------|
| 采样时间 | 13.5 cycles (~1.1μs) | 239.5 cycles (~20μs) |
| 采样次数 | 6 | 16 |
| 采样间隔 | 80μs | 200μs |
| 预读丢弃 | 1 次 + 80μs | 1 次 + 500μs |
| 滚动窗口 | 8 次平均 | 8 次平均（未变） |

## 5. 电量百分比映射表调整

### 5.1 背景

单节锂离子电池的放电曲线不是线性的：

- 4.2V → 满电
- 3.7V~4.0V → 最平坦的工作区间，电量下降慢
- 3.2V 以下 → 电压急速跌落，电量耗尽
- 3.0V → 基本是截止电压，应算 0%

### 5.2 修改前

```text
3300mV -> 0%
3400mV -> 5%
3550mV -> 15%
3700mV -> 35%
3850mV -> 60%
4000mV -> 80%
4200mV -> 100%
```

问题：0% 起点 3300mV 过高，3.85V 只显示 60%，不符合实际电池特性。

### 5.3 修改后

```text
3000mV -> 0%
3200mV -> 5%
3450mV -> 15%
3600mV -> 35%
3700mV -> 50%
3800mV -> 65%
3900mV -> 75%
4000mV -> 85%
4100mV -> 95%
4200mV -> 100%
```

改进点：

- 0% 起点从 3300mV 降到 3000mV，匹配锂电真实截止电压
- 中间段（3700~4000mV）给了更细的百分比分辨率，匹配最平坦的放电区间
- 3.84V 现在显示约 70%，而不是之前的 59%
- 满电 4.2V 仍然是 100%

### 5.4 关键电压对应表

| 电压 | 旧百分比 | 新百分比 |
|------|----------|----------|
| 3000mV | 0%（未定义，按流程也是0%） | 0% |
| 3100mV | 0% | 3% |
| 3300mV | 0% | 9% |
| 3500mV | 13% | 22% |
| 3700mV | 35% | 50% |

## 6. 硬件分压电路排查进展

### 6.1 已确认的事实

1. 电池两端电压约 3.9V+
2. 分压上端（接电池侧）对 STM32 GND 也是 3.9V+
3. BAT_SENSE 和 PA0 对 STM32 GND 都是 1.65V
4. OLED 修复前显示 3.06V（ADC 低读），修复后显示 3.84V

### 6.2 尚未完全解决的问题

理论上 100k/100k 分压中点应该是 `3.9V / 2 ≈ 1.95V`，但实测只有 `1.65V`。这意味着：

- 分压中点被额外下拉了约 0.3V
- 可能原因：PA0 引脚有微弱下拉、焊桥、走线漏电、或分压上端取样点实际不是纯电池正极
- 修复 ADC 采样时间后，软件侧读数已经从 `3.06V` 提升到 `3.84V`，接近万用表实测的 `1.65V × 2 = 3.30V`
- 剩余的 `3.84V` vs `3.9V` 的偏差约 1.5%，在可接受范围内

### 6.3 后续可做的硬件优化

1. **把分压电阻从 100k/100k 换成 10k/10k**
   - 源阻抗从 50kΩ 降到 5kΩ
   - ADC 采样更稳定
   - 代价：静态电流从约 21μA 增加到约 210μA

2. **排查 BAT_SENSE 被额外下拉的根因**
   - 临时断开 PA0 与 BAT_SENSE 的连接，再量中点电压
   - 如果中点回到 1.95V：问题在 STM32 侧
   - 如果中点仍是 1.65V：问题在分压网络本身
