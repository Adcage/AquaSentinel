## 5. 本轮未提交改动的核心内容

### 5.1 新增 BatteryMonitor

新增文件：

- `firmware/stm32-ptz/lib/battery_monitor/BatteryMonitor.h`
- `firmware/stm32-ptz/lib/battery_monitor/BatteryMonitor.cpp`

职责：

1. 周期性读取 `PA0`
2. 把 ADC 原始值换算成电池电压
3. 把电池电压映射成百分比
4. 提供平滑后的电量读数给 OLED 页面使用

### 5.2 采样与换算逻辑

当前按文档中的 1:1 分压换算：

```text
battery_mv = adc_raw × 3300 × 2 / 4096
```

软件侧为了减小高阻分压的波动，已经做了两层处理：

1. `analogReadResolution(12)`
2. `pinMode(PA0, INPUT_ANALOG)`
3. 每次采样先丢弃首样本
4. 连续采 6 次做一次平均
5. 再进入长度为 8 的滚动窗口平均

这样做的原因：

- `100k + 100k` 分压对 STM32F1 ADC 来说源阻抗偏高
- 直接单次 `analogRead()` 容易读低、抖动大

### 5.3 电量百分比分段映射

当前采用轻量分段映射，不是复杂 SOC 算法：

```text
3300mV -> 0%
3400mV -> 5%
3550mV -> 15%
3700mV -> 35%
3850mV -> 60%
4000mV -> 80%
4200mV -> 100%
```

### 5.4 OLED ASCII 字模补全

本轮还补了此前缺失的 ASCII 字模：

- `B`
- `W`
- `X`
- `%`
- `.`
- `-`

这是因为之前电量页上出现了这些现象：

- `BAT` 显示成 `AT`
- `RAW` 显示成 `RA`
- `SHORT NEXT` 显示成 `SHORT NE T`
- 百分号不显示

根因就是字模表缺少这些字符，被 OLED 渲染时直接吞掉了。

## 6. 当前用户实测与修复关系

用户最近一次板上反馈是：

1. `正在回中` 相关提示不完整
2. 电量页顶部不对
3. 页面里显示成：
   - `AT 1 71V`
   - `PCT 0`
   - `RA ...`
   - `SHORT NE T`

分析结果：

### 6.1 `AT 1 71V`

不是逻辑上真的叫 `AT`，而是：

- `BAT 1.71V`
- 缺 `B` 和 `.` 字模，导致被吞字

### 6.2 `RA`

其实是：

- `RAW xxxx`
- 但缺 `W` 字模，所以只剩 `RA`

### 6.3 `SHORT NE T`

其实是：

- `SHORT NEXT`
- 缺 `X` 字模，所以中间断了

### 6.4 `PCT 0`

可能有两层原因：

1. `%` 字模缺失，所以百分号看不到
2. ADC 实际读值偏低，导致换算百分比也确实接近 `0`

### 6.5 `1.71V`

这是当前最需要重新上板确认的点。

可能原因：

1. 之前采样方式太粗糙，高阻分压导致 ADC 读低
2. 软件已经改成“丢弃首样本 + 多次平均”，理论上会改善
3. 如果重新烧录后还是偏低，就要继续怀疑硬件侧稳定性

## 8. 当前最重要的下一步

### 8.1 必做：重新烧录并板级复测

在另一台设备继续前，优先执行：

```bash
cd firmware/stm32-ptz
pio run -e bluepill_f103c8 -t upload
```

重点看这几项：

1. 长按时是否完整显示 `正在回中`
2. 电量页标题是否显示 `电量`
3. `BAT` 是否完整显示，不再变成 `AT`
4. `RAW` 是否完整显示，不再只剩 `RA`
5. `SHORT NEXT` 是否完整显示
6. `PCT` 后面是否能显示 `%`
7. 电压是否仍然明显偏低
8. `RAW` 数值是否仍然大幅随机抖动

### 8.2 如果重新烧录后电压仍明显偏低

优先从硬件侧处理：

1. 在 `BAT_SENSE(PA0)` 与 `GND` 之间并联 `100nF` 电容
- 这是最推荐的第一步
- 对高阻分压 ADC 采样非常有效

2. 如果仍不稳定，再考虑把分压从：

```text
100k / 100k
```

改成：

```text
10k / 10k
```

代价：

- 静态耗电增加
- 但 ADC 稳定性会明显变好

### 8.3 如果重新烧录后电量页正常

建议立刻做两件事：

1. 把当前未提交改动提交成一个原子 commit
建议消息：

```text
feat(firmware): 为 STM32 接入电池电压采样与电量页显示
```

2. 然后继续下一阶段：
- `PB12` 超长按进入校准模式

1. 拉到当前最新提交基线
2. 恢复当前未提交改动
3. 重新编译一次：

```bash

pio run -e bluepill_f103c8
```

4. 烧录到板子：

```bash

```

5. 优先验证电量页和 `正在回中`
6. 如果正常，先提交电量采样改动
7. 再继续做超长按进入校准
